# 分析文档 + 置信度 / 吻合度：方案与文献地图

> 结论先说：**GitHub 没有这个功能，一行都没有。** 它给的是"把文档喂给模型"（Copilot Spaces）和"跑你自己代码的地方"（Actions），
> 「文档里每条断言被外部世界支持到什么程度」这件事，没有任何现成按钮。
> 而你这个项目其实已经把它的一半写好了（一手性 / 独立性 / 一致性 + 无 quote 不采信），缺的是
> ①把散文拆成原子断言 ②拿**独立**证据集去撞 ③把「吻合」和「一致」在数学上分开 ④校准。

---

## 0. 三个必须先定的事（否则做出来是装饰）

1. **循环比对**。文档用语料 A 写成，又拿去和网上比对 —— 若比对集还是 A，算出的不是「置信度」，是「复述准确率」。
   必须**留出集**：A 建文档，B 验真，A ∩ B = ∅ 且 owner 不相交。
2. **两个口径不能混**。「文档与它引用的证据一致」（faithfulness，对内，可自动判定）和「文档与外部独立来源一致」（agreement，对外，随世界变化）是两件事。
   一个文档可以 100% 忠实于自己的证据、同时与外部世界 60% 吻合 —— 这两个数的**组合**才有信息量，压成一个「置信度 0.82」就全丢了。
3. **PRD V1.1 的边界不能破**。PRD 第 40 行写着「不做事实裁决，只做来源透明度」。所以新指标只能叫
   **证据支持度 / 外部吻合度 / 来源独立性**，不能叫「真值」「真实性」。UI 给的是
   「6 个独立 owner 中 5 个表述与此一致，1 个给出不同数值」，不是「这是真的」。

## 2. 数据模型：文档不是散文，是断言图

文档级分数之所以经常是假的，是因为它算在「段落」上。必须落到**原子断言**：

    Doc
     ├─ Section[]           // 章节、顺序、权重
     └─ Claim[]             // 原子断言：一条一个可判真假的命题
          ├─ text           // 归一化后的命题（不是原文句子）
          ├─ quote          // 原文片段（沿用现有硬规则：无 quote 即丢弃）
          ├─ sourceIds[]    // 文档内部引用的证据
          ├─ kind           // quantitative | temporal | attribution | existence | causal | opinion | prediction（§9）
          ├─ checkWorthy    // 0~1，值不值得花检索预算去验
          └─ verdicts[]     // 外部核验结果，一条证据一个
               ├─ sourceId, owner, independent: boolean
               ├─ label      // support | contradict | neutral  ← 三态，不是二态
               ├─ score      // 0~1 NLI / 判定分
               └─ quote      // 证据原文片段（无 quote 的判定同样丢弃）

~~~ts
// src/lib/schemas.ts 追加
export const VerdictLabel = z.enum(["support", "contradict", "neutral"]);

export const VerdictSchema = z.object({
  sourceId: z.string(),
  owner: z.string(),
  independent: z.boolean(),   // 与文档引用集 owner 不相交（留出集）
  label: VerdictLabel,
  score: z.number().min(0).max(1),
  quote: z.string().min(1),   // 无 quote 的判定直接丢弃
  publishedAt: z.string().optional(),
});

export const DocClaimSchema = ClaimSchema.extend({
  id: z.string(),
  text: z.string().min(1),
  kind: ClaimKindSchema,   // 七类，取值表与权重写死在 src/lib/claim-kind.ts
  checkWorthy: z.number().min(0).max(1),
  verdicts: z.array(VerdictSchema).default([]),
});
~~~

**三态的理由**：neutral（检索到了、但没说这件事）既不是支持也不是反对。二态模型会把"没人提"算成"没有反证"，
这就是假共识的入口 —— 与你 PRD 批判 NAS 收敛度是同一个错误。

**命名与第四态**（已对齐 `docs/VERIFY-ARCH.md` §1.4）：verdict 用 `neutral`；界面上的第四态「不可核验」不由 verdict 决定，
而由 `claim.kind` 决定 —— 因果 / 观点 / 预测类断言拿到的是 `neutral`，但它们在统计口径上从不计入「已判定」。

## 3. 七个数字（不要合成一个）

| # | 指标 | 方向 | 定义 | 典型失败模式 |
|---|---|---|---|---|
| 1 | **支持度** S | 对内 | 有 quote 支撑的断言占比，按重要性加权 | 全部引用同一篇通稿 → 满分但无信息 |
| 2 | **朴素吻合度** A_raw | 对外 | support / (support + contradict)，不判权 | 被 50 个 SEO 农场刷满 |
| 3 | **有效吻合度** A_w | 对外 | 按 owner 可靠性 × 独立性加权 | 加权后才暴露假共识 |
| 4 | **一致性** κ | 内部 | 机会校正后的信源间一致（Fleiss κ / Krippendorff α） | 单一口径主导时 κ 甚至为负 |
| 5 | **有效独立源数** n_eff | 结构 | n_eff = (Σw)² / Σw² | 拿条数当独立度，10 家转载算 10 票 |
| 6 | **覆盖度** cov | 结构 | 文档断言覆盖到的"外部议题面"比例 | 只挑好核的说，吻合度虚高 |
| 7 | **校准度** ECE | 事后 | 报 0.8 的断言实际对了几成 | 从不测 → 分数只是装饰 |

### 3.1 为什么不能只用 1 - n_conflicts / n_checked

现在的 consistencyScore() 是未校正比例。它的问题不是"算错了"，是**尺度会骗人**：
某口径天然占绝对多数时，随机一致的概率本来就高，1 - 冲突率会把"没信息"报成"很一致"。

机会校正（Fleiss 1971；类别 >2 或有序用 Krippendorff α）：

    P_o = (1/N) Σ_i [ Σ_k n_ik(n_ik - 1) ] / [ m(m-1) ]
    P_e = Σ_k p_k²
    κ   = (P_o - P_e) / (1 - P_e)

实测一组 6 条断言 × 4 个判定者：**P_o = 0.667，P_e = 0.556，κ = 0.25**；同组数据 Gwet AC1 是 **0.40**。
差这么多不是算错，是**流行度悖论（prevalence paradox）**：类别分布越偏，κ 越保守。
所以别只报一个数 —— 报 κ 时把 P_e 一起显示，读者才知道这个 κ 在什么分布下得出。

### 3.2 n_eff：把"转载"从票数里扣掉（数学依据）

Condorcet 陪审团定理说人多就准，**前提是票独立**。Ladha (1992) 证明：一旦票与票相关，定理直接失效 ——
这正是 PRD 里"十家媒体转载同一通稿拿满分"的数学版本。所以票数要换成**有效票数**：

    n_eff = (Σ w_i)² / Σ w_i²          // Kish 有效样本量
    例：5 个来源，权重 [1, 1, 1, 0.6, 0.6] → n_eff = 4.74，不是 5

权重从三层来：
- **一手性**：一手 1.0，识别为转载 0.3（沿用 findSyndicatedIds）
- **owner 可靠性**：Dawid–Skene (1979) 的 EM，**不需要真值**就能估每个信源的混淆矩阵 —— truth discovery 的标准解
- **留出集**：只有 independent = true 的判定进 A_w；文档自己引用过的 owner 权重置 0（否则是自证）

### 3.3 有效吻合度与"假共识溢价"

    某断言 6 条证据：5 支持（3 条同源转载，权重 0.3 / 0.3 / 0.5）、1 反对（一手，0.8）
    朴素吻合度 = 5/6     = 0.833
    有效吻合度 = 3.1/3.9 = 0.795
    假共识溢价 = 0.833 - 0.795 = 0.038   ← 这个差值本身就该显示在 UI 上

溢价越大，"看起来一致"里水分越多。这比一个总分更能教用户读懂信源。

### 3.4 覆盖度：防"挑好核的说"

文档只写"能查到的"是天然倾向。拿外部**议题面**（aspect）对照：
证据按 (属性, 实体, 时间窗) 聚类成 aspect 集合 E，文档断言覆盖 E 的比例即 cov。
cov 低于阈值时 A_w 再高也不给高档 —— 与现有"一条断言都没交叉核对 → 封 0.64"同一精神。

### 3.5 文档级聚合与三条封顶

    C_doc = Σ_c m_c·s_c / Σ_c m_c        // m_c = 章节权重 × checkWorthy；s_c = 该断言的证据支持度

封顶（沿用 confidence.ts 的写法与语气）：
1. 被核验的断言质量占比 < 0.5 → C_doc = min(C_doc, 0.64)
2. 留出集独立 owner < 2 → min(C_doc, 0.45)（与现有软约束同一条线）
3. 全 fixture 证据 → min(C_doc, 0.34)

### 3.6 区间与校准：别报点估计

    Wilson 95%：38/41 支持 → [0.806, 0.975]；  3/3 支持 → [0.439, 1.000]

3/3 的区间下界只有 0.44 —— 小样本满分本该长这样。凡是报"吻合度 100%"而不报区间的地方，都在骗人。
校准（ECE / Brier + Murphy 分解）要等标注集，但**字段必须先留出来**，否则以后补不上。

## 7. 验收标准（可判定，不是形容词）

1. 任意文档产出 7 个数字，每个数字可展开到证据清单（沿用"徽章可展开"硬规则）。
2. 拿 20 篇已知结论的文档跑：分数 vs 人工判定做校准图，ECE ≤ 0.10 才算"置信度可以叫置信度"。
3. 造一批"10 家转载同一通稿"的语料：朴素吻合度应显著高于有效吻合度（溢价 > 0.15）；没差别说明权重没接上。
4. 留出集为空时，必须显式输出「无独立证据」，不得回落到文档自身引用集。
5. 全 fixture 时封顶 0.34（与现有规则一致）。
## 8. 界面契约：七个数字只上三个

七个数字全部露出来，读者会去做除法而不是读结论。界面只给三个，且每个都能展开到证据清单（验收第 1 条）。

| 位置 | 显示什么 | 什么时候出现 |
|---|---|---|
| 主徽章 | **有效吻合度** + Wilson 95% 区间（`0.72 [0.58, 0.83]`） | `verdicts` 非空且 `n_eff ≥ 2` |
| 副标签 | **有效独立源数** `n_eff`（hover 出「原始 N 条 / 疑似转载 K 条 / 去重合并 M 条」） | 恒显示 |
| 警示条 | **假共识溢价**（朴素 − 有效），> 0.05 才亮，橙底 | 仅检测到时 |

进 tooltip 的五个：朴素吻合度、Fleiss κ、Gwet AC1、未核验占比（neutral / judged）、档位封顶原因。

~~~ts
export const DOSSIER_VISIBLE_FIELDS = ["agreementEff", "nEff", "fakeConsensusPremium"] as const;
export const DOSSIER_TOOLTIP_FIELDS = [
  "agreementNaive", "fleissKappa", "gwetAc1", "silenceRatio", "capReason",
] as const;
~~~

五条文案规则（每条都能追到本文档前面某一节）：

1. **不说真/假**。标签只叫「外部吻合度」，工具提示写「与本文引用之外的独立材料的一致程度」。PRD V1.1 的边界（§0）决定这个数字不能承担事实裁决的语义。
2. **有 neutral 就必须并排写「未核验 K 条」**。单独一个大数字会让缺失被读成反面证据——沉默螺旋的界面版本（§5 文献 B）。缺的是「没查到」，不是「查到了相反的」。
3. **`n_eff < 2` 时主徽章写「无独立证据」，不给数字**，也不回落到文档自身引用集（验收第 4 条）。这是唯一允许用文字替代数字的位置。
4. **fixture 封顶 0.34 时**徽章加「演示数据」角标，tooltip 写明封顶原因；否则演示分数会被当真实分数转述。
5. **κ 与 AC1 必须成对出现**，并注明「κ < AC1 说明本批断言的类别分布偏斜，不是模型前后不一致」。单独一个 κ 会被当成 0~1 的成绩单读。

排序与降级：`agreementEff` 缺失 → 退到 `agreementNaive` 并加「未加权」小字；两者都缺 → 只显示 `n_eff` 与「未核验 K 条」，不显示任何百分比。任何情况下不出现没有分母的百分比。
## 9. kind 取值表（已写死进 `src/lib/claim-kind.ts`）

七类，前四类可核、后三类不可核。权重决定分子与分母，所以写死在代码里而不是配置里：改一个数，所有历史分数全部失效。

| kind | 能核 | 权重 | 判据（抽取时按此分类） | 例 |
|---|---|---|---|---|
| `quantitative` | 是 | 1.0 | 数字 + 单位 / 比率 / 金额 / 份额 / 排名 / 增幅 | 「数据中心收入 32 亿美元」 |
| `temporal` | 是 | 1.0 | 日期、时点、期限、先后、持续时长 | 「2026-10-24 生效」 |
| `attribution` | 是 | 0.9 | 谁说了 / 谁做的 / 谁拥有 / 谁任命 | 「黄仁勋表示…」「由 NVIDIA 收购」 |
| `existence` | 是 | 0.8 | 存在、上线、下架、具备某功能；无数字无时点 | 「该模型支持图像输入」 |
| `causal` | 否 | 0 | 因果连接词：导致 / 因为 / 推动 / 带动 / 使得 | 「涨价导致需求下滑」 |
| `opinion` | 否 | 0 | 评价或模糊程度：显著 / 看好 / 糟糕 / 值得 / 优于 | 「表现显著优于同行」 |
| `prediction` | 否 | 0 | 未来指向：将 / 预计 / 有望 / 计划 / 目标 | 「2027 年出货量翻倍」 |

**分类优先序**（一条断言同时符合多个时取第一个命中的）：

~~~
prediction > causal > opinion > quantitative > temporal > attribution > existence
~~~

理由两条，都是实测口径问题：

1. 「明年营收将达 500 亿」带数字但不可核 —— 按 quantitative 去核，判定器永远只能返回 neutral，于是它占着预算、把「未核验 K 条」这个数抬高，却不可能改变吻合度。
2. 「涨价导致毛利下降 3 个点」带数字但属于因果推断 —— 检索得到的证据最多给出相关，给不出因果。按定量判它，等于要求证据回答一个它答不了的问题。

**0.9 与 0.8 不是精度，是可核性折扣**：归属类断言的证据常常只有转述（二手引述 vs 原始声明），存在性断言往往只能找到「有」而找不到「没有」—— 两类都天然缺一侧。给 1.0 会把「找不到反例」当成「已经核过」。

**兜底方向是故意的**：模型没给 kind 时按 `existence`（0.8）处理。两侧代价不对称 —— 误判成可核只是多一次检索（判定器返回 neutral，不进分母）；误判成不可核则是把一个本来能核的说法永久踢出统计，而且用户在界面上看不见这条断言曾经存在过。

**与四态标签的映射**（`docs/VERIFY-ARCH.md` §1.4）：

| kind | verdict 正常结局 | 界面标签 | 进不进吻合度分母 |
|---|---|---|---|
| 前四类 | `support` / `contradict` / `neutral` | 已支持 / 存在矛盾 / 未找到证据 | support 与 contradict 进，neutral 不进 |
| 后三类 | 恒为 `neutral`（带「不可核验」理由） | 不可核验 | 从不进；只计入可核验率 `coverage` 的分母 |

所以 `coverage` 与 `fidelity` 的分母是两个不同的集合，这也是为什么它俩必须分开显示、绝不能相乘成一个百分比（§0）。

**代码位置**：`src/lib/claim-kind.ts`（`KIND_WEIGHTS` / `isVerifiableKind` / `claimWeight` / `VERIFIABLE_KINDS` / `UNVERIFIABLE_KINDS`）；类型定义在 `src/lib/schemas.ts` 的 `ClaimKindSchema`；权重表声明为 `Record<ClaimKind, number>`，新增一个 kind 而不补权重会直接编译失败。回归用例：`tests/claim-kind.test.ts`、`tests/verify.test.ts`。
