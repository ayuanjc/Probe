## 1. 产品概述

**产品定位**：一个面向 Geek 群体的 AI 原生高置信度情报终端。打破传统搜索引擎的“链接列表”模式，通过意图识别与多 Agent 协同，实时生成多维度的结构化数据面板（Generative UI）。

**目标用户**：极客、研究员、投资者、开发者（对数据来源敏感、容忍生成等待时间、偏爱自定义探索）。

**核心差异化**：

- **高置信度**：不编造事实，算法校验信源，拒绝 AI 幻觉。
- **生成式 UI**：搜索即生成动态仪表盘，而非返回死板网页。
- **克制分析**：默认只展示高密度数据与图表，用户主动追问时才进行 AI 深度分析。

---

## 2. 核心功能需求（Functional Requirements）

### 2.1 意图解析与搜索路由（Search Intent & Routing）

**查询分类**：利用轻量级模型对用户 query 进行意图二分：

- **Lookup（查找型）**：如“苹果 2025 Q3 财报”。系统优先返回高度结构化的核心数据卡片（KPI、时间线），不强行生成大满贯面板。
- **Exploratory（探索型）**：如“固态电池前景”。系统启动完整的 Agent 流水线，生成包含新闻列表、讨论度趋势、全球分布地图的复合面板。

**面板适配性判定**：规则 + 小模型判定，对于无需图表的查询（如查高铁时刻表），直接降级为高质量文本摘要。

### 2.2 数据检索与置信度算法（Data Retrieval & Confidence）

- **多源并发检索**：基于 Tavily API / GDELT / 历史趋势 API 抓取数据。
- **置信度打分系统**：在数据入库时进行两层打标：
  - **来源权威度**：核心媒体 > 聚合器。
  - **属性一致性**：通过算法（如 NAS 网络议程设置逻辑）计算多个信源对同一事件核心属性（时间、人物、地点）的收敛度。交叉印证越高，置信度越高。
- 面板需直观展示置信度徽章。

### 2.3 热点雷达与状态计算（Hotspot & Status）

- **公共热度榜**：被动搜索模式，后台定时任务（Cron）基于以下公式计算公开热点并生成 Top N 榜单。
- **热度公式（MVP 版本）**：

  \`\`\`
  热度分 = Magnitude（绝对注意力增量） + Deviance（偏差热度，即背离历史基线的程度） × 时间衰减因子
  \`\`\`

- **状态标签生成**：基于公式结果自动打标（爆发期、长尾期、争议态）。
- **情感对比**：若处于“争议态”，展示正负面新闻数量对比图（不写分析，只展示数据）。
- **命中展示**：用户搜索词若命中榜单，直接挂载热度状态徽章。

### 2.4 生成式 UI 与动态图表（Generative UI）

- **AI 生成 ECharts 配置**：前端不写死图表，大模型接收结构化数据后，输出严格的 ECharts JSON 配置（支持柱状图、树状图、全球地图等）。
- **渐进式渲染（Streaming）**：
  - Step 1：摘要 Agent 优先流式输出文本总结（解决等待焦虑）。
  - Step 2：图表 Agent 在后台并行生成，前端图表卡片“长出来”一块渲染一块。

### 2.5 模块化工作台与定制（Workspace）

- 前端基于 \`react-grid-layout\` 实现。
- **交互**：
  - 用户可自由拖拽、缩放图表卡片。
  - **一句话定制**：支持用户输入自然语言（如：“帮我加一个展示正负面情绪的饼图”），系统从模板库调用或由 AI 现场生成新模块插入面板。
- **布局快照**存入 Supabase，下次搜索恢复。

---

## 3. 交互与容错设计（UX & Error Handling）

- **视觉风格**：极暗黑风格（Dark Mode），毛玻璃特效（Glassmorphism），高密度数据排版（参考 Palantir / Perplexity），使用 Tailwind CSS 实现。
- **幻觉与报错降级**：
  - 若 AI 生成的 ECharts 配置解析失败，系统提示：“由于 AI 幻觉，当前图表无法生成。您需要重试吗？”
  - **自动降级**：重试仍失败，自动切换为渲染该数据的预设结构化表格，确保数据不丢失。

## 4. 技术架构与约束（Technical Specs）

- **全栈框架**：Next.js（App Router）+ TypeScript。
- **状态与鉴权**：Supabase（PostgreSQL + pgvector 用于向量检索）。
- **AI 编排**：Vercel AI SDK（处理流式）+ LangChain.js。
- **图表渲染**：ECharts + \`echarts-for-react\`。
- **界面布局**：\`react-grid-layout\`。

**Agent 流水线**：

| Agent | 职责 |
|---|---|
| Router Agent | 意图判定与拆分 |
| Retriever Agent | 多源抓取与翻译 |
| Analyzer Agent | 数据清洗、去重、置信度评估 |
| Coder Agent | 生成 ECharts JSON |

## 5. 迭代路线图（Roadmap）

### Phase 1（MVP 跑通闭环 — 1 个月）

- 实现极暗黑风格搜索框。
- 接入单一搜索 API（如 Tavily）。
- 实现“文本流式输出 + 生成一张基础折线图”的渐进式渲染。
- 无法实现复杂自定义，仅支持单列卡片流。

### Phase 2（引入复杂可视化与拖拽 — 2 个月）

- 接入多个数据源，实现多 Agent 协同。
- 引入 \`react-grid-layout\`，实现卡片拖拽与保存。
- 实现“一句话生成模块”功能。

### Phase 3（热度算法与实体图谱 — 3 个月）

- 上线后台定时热点计算任务。
- 引入 Neo4j 或向量库，实现人物/事物的树状关系图生成。
